# 쌓임쌓임 (Window Weather)

macOS의 창 위에 눈·비·낙엽·벚꽃·비눗방울·색종이를 표시하는 작은 앱입니다. Dock과 메뉴 막대에서 설정을 열 수 있습니다. 창의 윗변에는 눈과 잎·꽃잎·색종이가 쌓이고, 비는 물방울과 얕은 물막으로 반응합니다. 비눗방울은 창 위에 잠시 머무르다가 사라집니다. 효과는 회원가입·로그인·인터넷 연결 없이 로컬에서 실행합니다. 새 버전 확인과 다운로드에는 인터넷을 사용합니다.

첫 macOS 버전을 개발 중입니다. 창 이동, 전체 화면, Spaces, 여러 모니터에서의 실제 사용 검증은 아래 체크리스트를 따릅니다. Windows 지원은 향후 계획이며 현재 실행 파일을 제공하지 않습니다.

**0.6.0**은 **비눗방울과 색종이**를 추가한 버전입니다. 핵심 테스트 **68개**, 포커스 렌더링·설정 검사 **62개**, 눈사람 검사 **26개**, 창·컨트롤러 통합 검사 **44개**와 로컬 앱·DMG 서명·공증 검증을 완료했습니다. [0.6.0 검증 기록](docs/releases/0.6.0/VALIDATION.md)에 확인 범위를 정리했습니다. 설정창에서는 여섯 효과를 두 줄로 나누어 선택합니다. 한국어 이름은 **쌓임쌓임**, 영문 이름은 **Window Weather**이며, 기존 눈사람·설정 저장·Sparkle 업데이트 기능을 이어서 제공합니다. 이전 버전의 [0.5.1 검증 기록](docs/releases/0.5.1/VALIDATION.md), [0.5.0 검증 기록](docs/releases/0.5.0/VALIDATION.md), [성능 측정](docs/PERFORMANCE.md)은 해당 버전의 결과로 보관합니다.

## 다운로드와 업데이트

소스와 이후 배포는 [mindw96/WeatherWeather](https://github.com/mindw96/WeatherWeather) 저장소를 사용합니다. macOS 14 이상용 Apple Silicon·Intel 통합 앱입니다. **[0.6.0 DMG 다운로드 — 권장](https://github.com/mindw96/WeatherWeather/releases/download/v0.6.0/WindowWeather-0.6.0-macOS-universal.dmg)** · [앱만 담은 ZIP](https://github.com/mindw96/WeatherWeather/releases/download/v0.6.0/WindowWeather-0.6.0-macOS-universal.zip) · [릴리스 안내](https://github.com/mindw96/WeatherWeather/releases/tag/v0.6.0). 로컬 앱과 DMG의 Developer ID 서명·Apple 공증·공증 티켓·Gatekeeper 검사, 업데이트 EdDSA 서명을 완료했습니다. GitHub 공개 게시와 다운로드 다섯 파일의 SHA-256 무결성 검증, 실제 Sparkle의 최신/새 버전 판별도 완료했습니다.

0.5.0부터 [Sparkle 2.10.1](https://github.com/sparkle-project/Sparkle/releases/tag/2.10.1)이 새 버전을 하루에 한 번 확인합니다. 설정의 **자동 업데이트 확인**에서 끌 수 있으며, 설정창·앱 메뉴·메뉴 막대의 **업데이트 확인…**으로 직접 확인할 수 있습니다. 자동 다운로드·설치는 끄고 새 버전 알림에서 사용자가 설치를 선택하도록 했습니다. **0.5.0 이상 사용자는 앱 안에서 0.6.0을 확인하실 수 있습니다. 0.4.0 이하에는 Sparkle가 없으므로 최신 버전을 한 번 직접 설치해 주세요.**

DMG를 열고 앱을 옆의 `Applications` 폴더로 끌어 옮긴 다음, 응용 프로그램 폴더에서 실행해 주세요. 한국어 환경의 표시 이름은 **쌓임쌓임**이며 앱 파일 이름은 `WindowWeather.app`입니다. 설치 후 Finder에서 DMG를 꺼내셔도 됩니다. ZIP은 압축을 풀면 앱 하나만 나오며, 같은 방법으로 응용 프로그램 폴더에 옮겨 실행합니다. 사용 안내와 변경 내역은 릴리스 페이지에 있습니다.

`./script/release.sh`는 통합 Release 빌드·앱과 DMG의 Developer ID 서명·Apple 공증·티켓 첨부·EdDSA 업데이트 서명·최종 검증을 자동 진행합니다. 결과는 `dist/releases/0.6.0/`의 DMG, 앱만 담은 공유 ZIP과 업데이트 ZIP, `appcast.xml`, `SHA256SUMS.txt`입니다. 중단 후에는 `--resume`으로 같은 제출을 이어갑니다. 새 버전 번호·안내문 갱신과 GitHub 게시 절차는 [배포 문서](docs/RELEASING.md)에 있습니다.

## 실행하기

macOS 14 이상, Swift 5.9 이상이 포함된 Xcode 또는 Command Line Tools가 필요합니다. Sparkle 2.10.1을 Swift Package Manager로 받으므로 최초 빌드에는 인터넷 연결이 필요합니다. 버전과 체크섬은 고정되어 있습니다.

```sh
./script/build_and_run.sh
```

빌드 결과는 `dist/WindowWeather.app`과 `dist/WindowWeather-macOS.zip`입니다. 다른 폴더로 옮길 때는 ZIP을 풀어 사용하실 수 있습니다. 실행하면 설정창이 열리며, 닫거나 최소화한 뒤에는 **Dock 아이콘 클릭** 또는 **Dock 오른쪽 클릭 → 설정 열기…**로 다시 엽니다. 메뉴 막대의 날씨 아이콘 → **설정…**, 앱이 활성화된 상태의 **⌘,**도 사용할 수 있습니다. 설정창을 닫아도 효과는 계속되며 앱 메뉴의 종료 또는 **⌘Q**로 끝냅니다.

날씨 효과는 마우스 입력을 통과시키며, 눈사람의 보이는 몸체만 별도 작은 패널에서 드래그 입력을 받습니다. 동기화 폴더의 Finder 메타데이터와 서명이 충돌하지 않도록 임시 로컬 폴더에서 서명 후 ZIP과 실행용 앱을 생성합니다.

Codex의 **Run** 버튼도 같은 스크립트에 연결되어 있습니다. 생성된 앱은 현재 Mac의 아키텍처로 빌드하고 개발용 ad-hoc 서명을 적용합니다.

| 명령 | 용도 |
| --- | --- |
| `./script/build_and_run.sh --build-only` | 앱 번들만 빌드 |
| `./script/build_and_run.sh --verify` | 빌드·실행 후 프로세스 확인 |
| `./script/build_and_run.sh --smoke` | 짧은 실행 점검 |
| `./script/build_and_run.sh --previews` | 절차적으로 생성한 여섯 효과 미리보기 출력 |
| `./script/build_and_run.sh --validate-focus` | 여섯 효과의 포커스 창 숨김·복원과 설정 저장 검사 |
| `./script/build_and_run.sh --validate-snowman` | 눈사람 그림·표시 옵션·드래그 콜백·위치 복원 검사 |
| `swift test` | 핵심 시뮬레이션·창 경계 테스트 |

도구의 샌드박스 안에서 SwiftPM의 중첩 샌드박스가 막히는 경우에만 `WEATHER_DISABLE_SWIFTPM_SANDBOX=1`을 붙여 실행합니다. 동기화 폴더의 빌드 캐시가 느릴 때는 `WEATHER_BUILD_DIR=/private/tmp/window-weather-build`로 빌드 위치를 바꿀 수 있습니다. 결과 앱은 그대로 `dist/`에 생성됩니다.

설정창의 두 줄 선택 영역이나 메뉴에서 눈·비·낙엽·벚꽃·비눗방울·색종이를 선택하고 강도·바람·누적 여부를 바꾸실 수 있습니다. 일시정지하거나 쌓인 흔적을 지울 수도 있습니다. 종료하면 오버레이도 사라집니다. 설정은 `UserDefaults`에 로컬 저장합니다.

**전체 화면에서도 쌓기**는 기본적으로 꺼져 있습니다. 끄면 전체 화면 및 작업 영역을 가득 채운 최대화 창과 해당 화면 바닥에는 쌓이지 않고, 켜면 해당 창에도 쌓입니다. 누적 여부만 바뀌며 낙하 효과는 유지됩니다. 옵션을 끄는 순간 해당 창의 기존 누적도 지웁니다. 화면 맨 위에 맞닿은 전체 화면 창은 쌓인 효과가 화면 밖으로 잘리지 않도록 안쪽 윗부분에 표시합니다.

낙엽은 주황·금색·붉은 잎이 회전하며 떨어지고, 벚꽃은 연분홍 꽃잎이 더 천천히 흔들립니다. 닿은 잎과 꽃잎은 개별 모양으로 남았다가 서서히 사라집니다.

**비눗방울**은 반사광과 옅은 색 테두리를 가진 투명한 방울이 천천히 흔들리며 내려옵니다. **창 위에 비눗방울 머무르기**를 켜면 창 가장자리에 약 10초 머무른 뒤 살짝 커지면서 사라집니다. **색종이**는 여섯 색의 작은 종잇조각이 회전하며 떨어지고, 창 위에 쌓인 조각은 약 45초 동안 남았다가 끝부분에서 서서히 사라집니다. 두 효과 모두 기존 누적·전체 화면·작업 창 표시·일시정지·지우기 설정을 따릅니다.

**사용 중인 창에도 효과 표시**는 기본적으로 켜져 있습니다. 끄면 작업 중인 창 안의 여섯 효과와 그 창 위의 누적을 숨깁니다. 쌓인 흔적은 삭제하지 않고 시뮬레이션을 유지하며, 다른 창으로 전환하거나 다시 켜면 남아 있는 상태를 표시합니다. 전체 화면 누적 옵션과 독립적이고, 숨김을 선택한 창에는 전체 화면 누적을 켜도 효과가 보이지 않습니다.

접근성 권한 없이 활성 앱의 맨 앞 일반 창을 작업 중인 창으로 판단합니다. 앱 전환 시와 약 200ms 주기로 갱신하며, 별도 레이어의 도구 패널·작은 팝업 등은 실제 키보드 포커스 창과 다를 수 있습니다. 대상 창이 없으면 다른 창을 임의로 숨기지 않습니다.

**눈사람 표시**는 기본 ON이며 눈 모드에서만 나타납니다. 각 화면 오른쪽 아래에 처음 생기는 눈사람의 모자·몸통·팔을 잡아 같은 화면 안에서 끌어 옮기실 수 있습니다. 놓은 위치를 화면별 상대 좌표로 저장하고 재실행·일반적인 화면 크기 변경 후 복원합니다. 화면 식별자가 바뀌면 새 화면으로 인식해 기본 위치에서 시작할 수 있습니다.

눈사람 표시를 끄거나 다른 날씨 모드·일시정지로 전환하면 숨깁니다. 눈 누적 여부나 쌓인 흔적 지우기와는 독립적입니다. 포커스 창의 효과를 숨긴 경우 겹친 눈사람 부분도 가려지고 해당 부분은 잡을 수 없습니다. 설정 미리보기는 표시 여부를 반영하며 실제 위치 이동은 화면 위 눈사람을 대상으로 합니다.

## 구현과 현재 범위

- **WeatherCore:** OS 창 API에 의존하지 않는 입자 시뮬레이션과 창 경계 계산입니다. 눈·물막, 낙엽·벚꽃·비눗방울·색종이의 움직임과 개별 정착 입자, 겹친 창의 노출 구간, 전체 화면 누적 정책과 눈사람 상대 위치 계산을 다룹니다.
- **WeatherApp:** AppKit 오버레이, SwiftUI 설정, Sparkle 업데이트 확인, 읽기 전용 창 geometry 수집을 제공합니다. 화면당 투명 패널을 사용하며, 창 정보는 초당 5회, 애니메이션은 일반 상태 초당 30회·저전력 상태 초당 20회 갱신하도록 구성했습니다.
- **검증:** 자동 테스트는 물리 규칙과 창 가림 계산을 검증합니다. 미리보기는 실제 데스크톱 화면 캡처가 아닌 생성된 예시이므로 OS의 창 합성과 동일한 검증으로 보지 않습니다. 최종 실행 검증 상태는 [PLAN.md](PLAN.md)에 기록합니다.

Dock 위 적설, 번개, 로그인 시 자동 실행과 Windows 버전은 첫 구현에 포함하지 않습니다. 최신 공유 패키지의 서명·공증 상태는 위 배포 안내를 따릅니다. 창 모서리와 비정형 창은 사각형 geometry를 기준으로 근사합니다.

실제 날씨에 따라 눈·비를 자동 선택하는 기능은 이번에는 **가능성만 검토**했습니다. [날씨 연동 검토](docs/WEATHER_INTEGRATION.md)에 공급자·배포 방식·위치 선택·비용과 오프라인 처리를 정리합니다. 앱에는 날씨 조회나 위치 권한 요청을 추가하지 않았으며 효과는 사용자가 선택합니다.

## 개인정보와 권한

앱은 창 정보 중 **위치·크기·창 ID·레이어·불투명도·소유 프로세스 ID**를 필터링과 충돌 계산, 활성 앱의 창 식별에 사용합니다. 창 제목이나 내용은 사용하지 않으며, 화면 이미지·키보드 입력·계정 정보·분석 로그를 수집하거나 전송하지 않습니다. 창 목록과 프로세스 ID는 파일로 저장하지 않습니다.

눈사람의 클릭 영역 판정에는 현재 포인터 위치를 메모리에서 사용하며, 마우스를 놓은 뒤 눈사람의 상대 위치만 화면별로 저장합니다. 포인터 이동 기록은 저장하지 않습니다.

업데이트 확인은 GitHub Releases의 HTTPS appcast를 조회합니다. 업데이트 ZIP은 Sparkle EdDSA 서명과 Apple 코드 서명으로 검증하며, Sparkle 시스템 프로파일 전송은 비활성화했습니다. 공개 키만 저장소에 포함하고 개인 서명 키는 개발자의 Mac 키체인에 둡니다. 날씨·창·포인터 정보는 업데이트 요청에 포함하지 않습니다.

현재 구현에는 화면 기록 권한을 요청하는 API나 Accessibility API가 없습니다. macOS에서 제공하는 창 정보의 범위가 달라지는 경우에도 권한을 자동 요청하지 않습니다. 창이 감지되지 않을 때는 먼저 일반 앱 창을 열고 설정의 감지 상태를 확인해 주세요.

창 geometry의 기준은 [Apple의 Required Window List Keys](https://developer.apple.com/documentation/coregraphics/required-window-list-keys)를 참고했습니다.

## 직접 확인할 항목

- 효과가 켜진 상태에서 다른 창을 클릭하고 입력·스크롤할 수 있는지
- 창을 이동·크기 조정·최소화·닫을 때 눈과 물막이 잘 따라가는지
- 겹친 창에서 가려진 창의 적설선이 앞 창을 뚫고 나오지 않는지
- Mission Control·Spaces·전체 화면 전환 뒤 오버레이가 정상으로 돌아오는지
- 서로 다른 배율의 모니터를 좌우·위아래로 배치했을 때 좌표가 맞는지
- 잠자기 복귀, 모니터 연결 해제, 저전력 상태에서 앱이 멈추거나 과도하게 바빠지지 않는지

이 항목들은 자동 테스트만으로 완료했다고 판단하지 않습니다. 특히 전체 화면과 Spaces의 표시 정책은 실제 사용 환경에서 추가 확인이 필요합니다.

## 설계 자료와 Windows 계획

[REA.md](REA.md)는 지정된 Koi 앱의 정적 분석 근거와 한계를, [PLAN.md](PLAN.md)는 구현 단계와 남은 검증을 정리합니다. 시각적 아이디어와 동작을 참고했으며 Koi의 코드·셰이더·아이콘·배경·음원은 포함하지 않습니다.

Windows에서는 창 열거, 투명 오버레이와 모니터 DPI 처리를 별도 구현해야 합니다. Foundation 기반 핵심 모델의 Swift Windows 도구 체인 호환성을 먼저 검증하고, 실용적이지 않으면 동일한 결정적 규칙과 테스트 입력을 이식할 계획입니다. 현재 macOS 코드가 그대로 Windows 앱이 된다고 가정하지 않습니다.
