# 로컬 검증 기록

검증일: 2026-11-05, Asia/Seoul. 최신 검증 대상: **0.2.0 (2)**. macOS arm64 호스트, Swift 6.4.2, 연결된 화면 2개. 프로젝트의 최소 지원 선언은 macOS 14이며, macOS 14 실기기와 Intel Mac에서 실행한 결과는 아닙니다.

## 공유 패키지 작업 중 발견한 검증 한계

2026-11-05 후속 확인: 아래 26개 통과는 당시 개발 빌드의 기록입니다. 전체 화면 완료 대기에서 `styleMask.fullScreen`을 사용했는데, 이 값은 전환 완료보다 먼저 바뀔 수 있으므로 전체 화면 Space 진입 완료를 확정하는 근거로는 부족합니다. 검증 도구는 `didEnterFullScreenNotification` / `didExitFullScreenNotification`을 기다리도록 보완했습니다. 공유 패키지 재검증 당시 Mac이 잠겨 있었고 창 활성화와 geometry가 달라져 GUI 재검증을 보류했습니다. 공유 ZIP의 서명·아키텍처·최종 검증 상태는 [별도 기록](../releases/0.2.0/VALIDATION.md)을 따릅니다.

테스트 명령:

```sh
swift test --disable-sandbox \
  --cache-path /private/tmp/window-weather-swiftpm-cache \
  --scratch-path /private/tmp/window-weather-core-build

WEATHER_BUILD_DIR=/private/tmp/window-weather-final-build \
  /bin/bash ./script/build_and_run.sh --smoke

WEATHER_BUILD_DIR=/private/tmp/window-weather-final-build \
  /bin/bash ./script/build_and_run.sh --previews
```

테스트의 `--disable-sandbox`는 도구 환경에서 SwiftPM의 중첩 샌드박스 제약을 피하기 위한 옵션입니다. 앱 실행 점검과 최종 스크립트 빌드는 이 옵션 없이 수행했습니다. 프로젝트가 동기화되는 Documents 폴더에 있어 한 번 빌드 캐시 읽기가 지연되었습니다. 임시 로컬 빌드 경로를 사용한 재빌드로 진행했으며, 결과 앱은 프로젝트의 `dist/`에 있습니다. 새로 생성한 번들에 붙는 Finder 메타데이터로 서명이 실패하는 경우도 스크립트에서 해당 장식 속성만 제거해 처리했습니다.

File Provider는 서명 뒤에도 작업 폴더의 `.app` 디렉터리에 `com.apple.FinderInfo`를 다시 붙였습니다. 그 상태의 디렉터리는 엄격한 코드 서명 검사에서 거절되지만, 생성 앱의 로컬 실행은 확인했습니다. 이 확장 속성을 포함하지 않는 `dist/WindowWeather-macOS.zip`도 만들었고, ZIP을 임시 로컬 폴더에 푼 앱은 엄격한 서명 검사를 통과했습니다. 옮겨 사용할 때는 ZIP을 권장합니다. 이 검사는 개발용 ad-hoc 서명의 무결성 확인이며 Apple 공증 확인이 아닙니다.

## 실제 앱에서 확인한 항목

1. 화면마다 오버레이가 하나씩 생성됩니다.
2. 패널의 마우스 통과, 비활성·비포커스, 투명 속성을 확인했습니다.
3. Core Graphics가 실제 테스트 창을 감지하고 표면을 만듭니다.
4. 창의 위치 변경과 크기 변경이 반영됩니다.
5. 실행 중 입자가 생성됩니다.
6. 다른 모니터로 창을 옮긴 뒤에도 이전 적설량이 유지됩니다.
7. 일시정지가 패널을 숨기고, 재개가 다시 표시합니다.
8. 누적 지우기가 모든 실제 화면의 높이를 지웁니다.
9. 닫힌 창의 표면이 제거됩니다.
10. 낙엽과 벚꽃 모드의 입자 생성·정착과 지우기를 확인했습니다.
11. 실제 창을 작업 영역에 맞춰 최대화한 뒤 전체 화면 누적 옵션 OFF에서 표면·바닥이 제외되고, ON에서 다시 쌓이고, OFF로 바꾸면 기존 누적이 지워집니다.
12. `NSWindow.toggleFullScreen`으로 실제 전체 화면 Space에 진입·복귀했습니다. OFF일 때 표면 제외와 ON일 때 화면 안쪽 누적 표면 복원을 확인했습니다.

위 묶음은 `smoke.json`의 개별 assertion 26개에 대응합니다. 마지막 실행에서 테스트 창을 닫은 뒤 기존 창 8개가 감지됐습니다. 창 제목·내용·ID 목록은 저장하지 않았습니다. 검증 모드는 별도 설정 도메인을 사용하며 종료할 때 해당 도메인을 지웁니다.

화면 간 적설 전달 테스트는 주변 앱이 테스트 창을 가리는 경우에도 동일한 초기 상태가 되도록 독립 시뮬레이션의 높이를 테스트 창에 넣고 시작합니다. 이후 실제 창을 다른 모니터로 옮겨 geometry 수집·호스트 전달을 확인합니다. 초기의 비활성 테스트 창/다른 창 가림에 의존한 실행에서는 이동 또는 초기 적설량 확인이 실패했습니다. 테스트 창 활성화, 실제 최종 frame 기준 비교, 초기 누적 고정 후 최종 26개가 통과했습니다. 진단에는 이 테스트 창의 전후 좌표·누적량만 저장했습니다.

## 남아 있는 실사용 확인

클릭 통과는 패널 속성으로 검증했으며 실제 마우스 클릭·드래그·스크롤·키보드 입력을 자동 주입하지 않았습니다. 자체 테스트 창의 전체 화면 진입·복귀는 확인했지만 다른 앱들의 모든 Spaces·Mission Control 조합, 잠자기·잠금 복귀, 화면 연결 해제와 서로 다른 배율·위아래 모니터 배치는 추가 수동 확인이 필요합니다. 30/20 Hz는 설정한 목표 주기이며 측정된 FPS·CPU/GPU·배터리 결과가 아닙니다.

전체 화면 여부는 별도의 접근성 권한으로 상태 플래그를 읽지 않고 화면 전체·안전 영역·작업 영역에 네 변이 2pt 이내로 일치하는지 판정합니다. 따라서 작업 영역을 가득 채운 최대화 창도 옵션 적용 대상입니다. ON일 때 맨 위 경계는 필요한 경우 화면 안쪽 20pt에 누적 표면을 둡니다. 기본 OFF이며 낙하 효과 자체를 중지하지는 않습니다.

현재 도형은 창의 사각형 경계를 기준으로 합니다. 둥근 모서리와 비정형 투명 창을 픽셀 단위로 복구하지 않으며, 창 추적은 약 200ms 간격입니다. 화면 구성 자체가 바뀌면 패널을 다시 만들며 누적 상태를 초기화합니다. 화면 사이에 걸친 같은 창은 높이 배열을 5 Hz로 병합하므로 경계의 한 샘플에 동시에 닿는 입자의 질량까지 정확히 더하는 유체 모델은 아닙니다.

Windows 실행 파일, 배포용 Developer ID 서명·공증, 공개 GitHub 원격 저장소나 릴리스는 이번 로컬 MVP 결과에 포함하지 않습니다.
