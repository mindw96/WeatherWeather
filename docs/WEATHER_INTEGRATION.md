# 실제 날씨 연동 검토

검토일: **2026-11-05 (Asia/Seoul)**. 대상은 macOS 14 이상, GitHub Releases의 Developer ID 서명·공증 DMG/ZIP으로 배포하는 **쌓임쌓임**입니다.

**눈이 오면 눈, 비가 오면 비를 기본 효과로 선택하는 기능은 구현 가능합니다.** 이번 작업에서는 가능성과 조건만 검토했습니다. 날씨 조회 코드·위치 권한·네트워크 요청·계정 설정·유료 구독은 추가하지 않았습니다.

## 권장 방향

현재처럼 비상업 오픈소스 앱을 Mac과 이후 Windows에 제공하려면 **Open-Meteo + 사용자가 선택한 도시 + 선택형 자동 연동**으로 시작하는 것이 가장 간단합니다. 최종 사용자는 회원가입이나 API 키 입력 없이 사용할 수 있습니다. 이는 아래 공식 API·약관과 현재 배포 방식에 근거한 설계 제안이며, 실제 연결 검증 결과는 아닙니다.

Apple의 기본 날씨 앱에 표시된 도시·즐겨찾기·현재 화면 값을 그대로 읽는 공개 연동 API는 이번에 확인한 공식 문서에서 찾지 못했습니다. Apple이 제공하는 개발자 경로는 **WeatherKit으로 지정한 좌표의 날씨를 별도로 조회**하는 방식입니다. 따라서 기본 날씨 앱의 저장 데이터를 읽거나 비공개 파일·API에 의존하는 방식은 계획하지 않습니다. 별도 조회는 위치·갱신 시각에 따라 기본 앱 화면과 차이가 날 수 있습니다. [Apple WeatherKit 안내](https://developer.apple.com/weatherkit/), [WeatherKit 사용 예제](https://developer.apple.com/videos/play/wwdc2022/10003/)

| 방법 | 현재 앱에 대한 판단 | 계정·배포·운영 조건 |
| --- | --- | --- |
| **Open-Meteo HTTP API** | 현재 목적의 우선 후보. Mac·Windows에서 같은 응답 규칙을 사용할 수 있습니다. | 무료 API는 비상업 용도이며 API 키 없이 요청할 수 있습니다. 호출 한도·출처 표시·서비스 장애 처리가 필요합니다. |
| **Apple WeatherKit Swift 프레임워크** | macOS 버전 조건은 충족하지만 **현재 Developer ID 배포의 지원 경로가 아닙니다.** | Apple의 macOS capability 표에서 WeatherKit은 ADP 열만 지원 표시가 있고 Developer ID 열은 비어 있습니다. App Store 경로라면 App ID의 서비스·capability와 entitlement 구성을 별도로 검토해야 합니다. |
| **Apple WeatherKit REST API** | Apple 날씨를 꼭 사용하거나 Windows까지 같은 공급자를 쓰려면 가능한 대안입니다. | 개발자 토큰 서명용 개인 키를 앱·공개 저장소에 넣을 수 없습니다. 키를 보관하고 요청/토큰을 관리하는 서버가 추가로 필요합니다. 사용자 로그인 UI는 필수 조건이 아닙니다. |

근거: [Open-Meteo API 문서](https://open-meteo.com/en/docs), [Apple macOS capability 지원표](https://developer.apple.com/help/account/reference/supported-capabilities-macos), [WeatherKit REST 인증](https://developer.apple.com/documentation/weatherkitrestapi/request-authentication-for-weatherkit-rest-api). Apple 표는 검색 결과에서 체크 아이콘이 생략되어 원문 HTML의 WeatherKit 행과 ADP/Developer ID 열을 대조했습니다. `com.apple.developer.weatherkit`을 서명에 임의로 붙이면 현재 배포에서 바로 동작한다고 가정하면 안 됩니다.

## 비용과 출처 표시

- **Open-Meteo 무료 API:** 비상업 용도에 한합니다. 공식 약관은 분당 600회·시간당 5,000회·일 10,000회 한도와 월 300,000회 표를 제시하며, IP와 애플리케이션에 한도를 적용합니다. 오픈소스라는 이유만으로 상업적 배포까지 무료가 되지는 않습니다. 광고·구독 등 상업 모델을 추가하거나 사용량이 커지면 유료 서비스 조건을 다시 검토해야 합니다. 무료 서비스에는 가동 시간 보장이 없습니다. [이용 약관](https://open-meteo.com/en/terms), [가격 안내](https://open-meteo.com/en/pricing)
- **Open-Meteo 데이터:** CC BY 4.0에 따른 출처·라이선스 링크와 가공 사실 표시가 필요합니다. 설정의 날씨 연동 영역에 `날씨 데이터: Open-Meteo · 효과로 변환`과 출처 링크를 제공하는 구성을 제안합니다. 데이터 라이선스와 Open-Meteo 서버 소스의 AGPL 라이선스는 별개입니다. [데이터 라이선스](https://open-meteo.com/en/licence)
- **WeatherKit:** Apple Developer Program 멤버십당 월 500,000회가 포함되며 초과 용량은 별도 구독입니다. 사용 형태에 맞는 Apple Weather 및 데이터 출처 표시가 필요합니다. 애니메이션으로 변환한 경우에도 출처 의무가 자동으로 없어지는 것은 아닙니다. [Apple 요금·표시 안내](https://developer.apple.com/weatherkit/)

가격과 약관은 바뀔 수 있으므로 실제 구현·배포 전에 다시 확인해야 합니다. 이번 검토에서는 구독이나 서버를 생성하지 않았습니다.

## 제안하는 동작

자동 연동은 기본 OFF로 두고, 켠 사용자의 선택 지역에 대해서만 조회하는 구성을 권합니다. 아래 표는 **구현 전 제안 정책**입니다.

| 현재 날씨 | 기본 효과 | Open-Meteo 코드 예시 |
| --- | --- | --- |
| 눈·눈 소나기·싸락눈 | 눈 | `71, 73, 75, 77, 85, 86` |
| 이슬비·비·소나기·어는 비 | 비 | `51, 53, 55, 56, 57, 61, 63, 65, 66, 67, 80, 81, 82` |
| 뇌우·우박 | 현재 강수량이 있을 때 비로 단순화 | `95, 96, 99`; 우박 전용 효과는 범위 밖 |
| 맑음·구름·안개 | 사용자가 선택한 기본 효과 | 눈·비를 임의로 추정하지 않습니다. |
| 비와 눈이 함께 확인됨 | 우선 눈으로 표현 | 강설량이 양수이면 눈 우선이라는 앱 정책. 물리적 강수 분류와 구분합니다. |
| 응답 오류·알 수 없는 코드·오래된 값 | 최근 유효값을 잠시 유지한 뒤 기본 효과 | 기본값을 비나 눈으로 단정하지 않습니다. |

코드 의미는 [Open-Meteo 현재 날씨와 WMO 코드 문서](https://open-meteo.com/en/docs)를 따릅니다. 특히 어는 비를 단순히 영하라는 이유로 눈으로 바꾸지 않습니다. 자동 선택은 **현재 시각의 날씨**를 기준으로 하고, 하루 대표 예보나 강수 확률만으로 지금 비가 온다고 판단하지 않습니다. Open-Meteo의 현재 값은 기상 모델을 기반으로 하므로 창밖 실황과 완전히 일치하거나 즉시 반영된다는 보장은 없습니다.

제품 동작은 다음 정도면 충분합니다.

1. 사용자가 자동 연동을 켜고 도시를 선택하면 현재 날씨를 한 번 조회합니다. 이후 앱 실행 중 약 15~30분 간격과 잠자기 복귀 시 갱신하되, 중복 요청은 합칩니다.
2. 네트워크 요청은 애니메이션 루프와 분리하고 시간 제한·재시도 간격을 둡니다. 상태에는 선택 지역과 마지막 갱신 시각을 표시합니다.
3. 응답의 좌표·시각·코드·유한한 수치를 검증합니다. 오래된 캐시를 현재 날씨로 표시하지 않고, 예를 들어 최대 1시간 뒤에는 사용자 기본 효과로 돌아갑니다. 이 시간은 구현 시 확정할 제품 정책입니다.
4. 수동으로 비눗방울·색종이 등 다른 효과를 고르면 자동 연동을 잠시 해제하고, 사용자가 다시 자동을 선택할 때 재개합니다. 자동 선택이 사용자의 기본 효과·강도·바람·눈사람 설정을 덮어쓰지 않게 합니다.

## 위치와 개인정보

**도시 직접 선택을 먼저 제공**하면 macOS 위치 권한이 필요 없습니다. 도시 검색은 검색어를 지오코딩 서비스에 보내 좌표를 받는 과정이므로, 선택한 도시와 좌표만 로컬에 저장하고 상세 주소는 요구하지 않는 구성을 권합니다. 한국어 도시 검색과 국가/행정 구역 구분은 Open-Meteo 지오코딩 API로 구성할 수 있습니다. [지오코딩 문서](https://open-meteo.com/en/docs/geocoding-api)

나중에 `현재 위치 사용`을 추가한다면 사용자가 해당 버튼을 누를 때만 Core Location 권한을 요청해야 합니다. macOS에는 위치 사용 목적 설명이 필요하며, When in Use와 Always는 Mac에서 기능상 동등합니다. 이 기능에는 이동 경로를 계속 추적할 필요가 없으므로 일회성 또는 드문 위치 갱신으로 충분합니다. 거부·위치 서비스 꺼짐 상태에서는 도시 선택을 계속 사용할 수 있게 합니다. [Apple 위치 권한 안내](https://developer.apple.com/documentation/corelocation/requesting-authorization-to-use-location-services)

자동 연동을 켜면 선택 좌표와 일반적인 요청 정보가 날씨 제공자에게 전달됩니다. Open-Meteo는 무료 API의 문제 해결 로그에 좌표가 포함될 수 있고 로그를 90일 뒤 삭제한다고 안내합니다. 따라서 `기기 밖으로 아무 정보도 전송하지 않는다`고 안내할 수는 없습니다. 수동 효과 모드는 계속 오프라인으로 동작하게 유지합니다. [Open-Meteo 개인정보 안내](https://open-meteo.com/en/terms#privacy)

## 아직 수행하지 않은 것

실제 날씨 API 호출, 현재 위치 조회, WeatherKit entitlement·프로비저닝 변경, API 키 발급, 도시 선택 UI와 자동 전환 구현은 하지 않았습니다. 한국 내 위치별 체감 정확도, 공급자 장애·호출 한도 상황, 장시간 전력 사용량은 향후 별도 검증이 필요합니다. 이번 결론은 공개 공식 문서와 현재 앱의 배포 조건에 따른 가능성 검토입니다.
